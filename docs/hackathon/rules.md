# Into the Scrape-Verse — Rules & Guidelines

> **Official Source**: [https://www.wemakedevs.org/hackathons/scrape-verse/rules](https://www.wemakedevs.org/hackathons/scrape-verse/rules)
> **Code of Conduct**: [https://wemakedevs.org/coc](https://wemakedevs.org/coc)

---

## 1. Eligibility & Participation

- **Location**: Global participation online from anywhere in the world (or optional in-person on August 22 in San Francisco).
  - *Note*: Bright Data's platform is not accessible in Pakistan and Iran, so the hackathon is not open to participants in those two countries.
- **Team Size**: Solo or teams of up to **4 members**. Each participant may only belong to one team.
- **Start Time**: Main coding and design work must begin after the hackathon starts on August 17. Ideas, architecture diagrams, notes, and planning can be prepared beforehand.

---

## 2. Technical & Project Requirements

- **Required Platform**: Every project **must use Bright Data Scraper Studio** to create and run a custom web scraper.
- **Custom Scrapers Only**: Using only an existing ready-made scraper from the Bright Data Scrapers Library does *not* qualify. Your submission must include a custom scraper created via Scraper Studio.
- **Public Data Only**: Projects must use publicly available web data. Do *not* scrape private, login-protected, paywalled, or sensitive personal information.
- **Open Stack**: You may use any frameworks, open-source libraries, public APIs, templates, third-party tools, or UI kits. Original work done during the hackathon will be evaluated.

---

## 3. Mandatory Submission Checklist

Every submission must provide:
1. **Public Source Code Repository** (e.g., GitHub / GitLab).
2. **Comprehensive `README.md`** explaining setup, architecture, and features.
3. **Example Structured Output** (e.g., sample JSON or CSV extracted from the target website).
4. **Demo Video** demonstrating the working application and the scraper in action.
5. **Clear Explanation** of how Bright Data Scraper Studio & self-healing was utilized.

---

## 4. AI Tool Usage Policy

- AI coding assistants (such as Claude Code, Cursor, Codex, Gemini/Antigravity) are allowed and encouraged, but their use must be disclosed.
- Participants must understand their submitted code, project architecture, and technical decisions.
- Projects that are 100% blindly generated with no participant contribution, verification, or understanding may be rejected.

---

## 5. Intellectual Property & Code of Conduct

- **Ownership**: All intellectual property developed during the hackathon belongs completely to the participant or team that created it.
- **Fair Play**: Harassment, plagiarism, or attempting to manipulate the judging process results in immediate disqualification.
